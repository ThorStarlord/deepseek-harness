# Agent Note: 与声明和风险相称的 UI 证据

Status: proposed

[English](2026-11-16-claim-proportionate-ui-evidence.md) | 中文

## 问题

当前浏览器 GIF 规则要求每项用户可见的 GUI 变更都附带真实服务器和真实模型 GIF。对于本地呈现或持久化声明，这项要求可能与实际行为无关；而 GIF 本身也不能证明行为、provider 集成或用户接受。若没有明确的证据标准就替换这一统一规则，可能削弱对实时 provider 行为或受保护交互的审查。

## 提案

在所有者明确批准并集成确切替代方案后，前瞻性地将按声明和风险选择证据的政策应用于仓库中的用户可见 GUI 变更。在此之前，当前要求继续生效，包括 PR #33 和 PR #34；本提案不得追溯性地使这些 PR 符合要求。

根据变更行为、每项验收声明以及变更涉及的最高风险选择证据。UI 行为发生变化时，要求有针对性的测试和对已组装应用的检查。静态状态使用截图；当序列、时序或中间状态很重要时使用视频。视频或截图是呈现证据，不能代替行为测试或独立评估。如果实时 provider 行为属于验收标准，缺少实时证据会使 PR 不合格，直至取得证据或所有者修改已接受的范围。

对于本地持久化和 Activity 协调，如果相应声明适用，则要求有针对性的行为、重启、无法解析的引用和恢复证据，并检查实际呈现的交互。不能仅仅因为这些功能出现在 GUI 中就要求模型调用。

provider 执行、身份验证和外部副作用声明需要有针对性的确定性测试、实际呈现的交互，以及当前审查政策要求的独立技术/安全和产品/设计评估。只有在可行时取得直接真实 provider 证据，才能声明实时 provider 行为。如果无法调用 provider，应将该行为记录为未经验证，不得暗示已产生实时结果。

权限、身份、破坏性副作用和其他受保护要求仍由现有安全和授权政策负责。证据选择不会改变审查者资格、审查处置、原生 provider 控制，也不会扩大仅适用于 Issue #17–#30 的 Stage 1 Agent 辅助评估例外。

每项证据都应记录审查提交、来源、模式，以及它来自实时 provider、确定性测试、回放还是静态检查。区分观察到的事实与解释，说明剩余的不确定性；当风险或证据支持的声明不明确时，采用较严格的要求。

## 考虑过的替代方案

- **每项 GUI 变更都要求真实模型 GIF。** 这保留了统一的材料规则，也能显示交互序列，但会为本地行为声明强制调用 provider，并可能让人误以为 GIF 已证明它没有测试的行为。
- **所有 GUI 变更只使用测试。** 这免去了录制成本，但不能展示已组装的界面或交互状态，也可能漏掉呈现缺陷。
- **所有 GUI 变更只使用静态截图。** 这能为稳定状态提供直接的呈现证据，但无法显示交互序列或时序，也不能证明 provider 行为。

## 验收标准

- UI 审查技能定义声明与风险矩阵、确切的呈现证据要求、混合风险升级方式，以及对未经支持的实时声明进行失败关闭的处理。
- GIF 技能说明何时需要录制，并要求注明所演示的提交 SHA、提供服务的树、来源和运行模式，同时保留凭据安全、材料检查以及对实时和模拟声明的如实描述。
- 政策保持现有审查权限和原生授权保护，不追溯性地使先前的 PR 符合要求。即使本政策已集成，PR #33 和 PR #34 仍须满足现有资格要求，包括基于精确构建树的真实服务器／真实模型 GIF。
- 所有者批准确切替代政策之前，完成双语 Agent Note 和文档检查。

## 风险

审查者可能把 provider 或外部副作用变更归类为本地变更，从而选择不足的证据。因此，由变更和声明中的最高风险决定要求；遇到不明确情况时使用较严格的标准。静态证据可能遗漏短暂失败或时序，因此这些状态很重要时应使用视频。直接证据仍可能不完整，所以缺少 provider 证据时应明确标为未经验证，未解决的验收声明也不能视为已合格。
