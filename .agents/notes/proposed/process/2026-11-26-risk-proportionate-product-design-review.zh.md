# Agent Note: 风险比例化的产品/设计评审

Status: proposed

[English](2026-11-26-risk-proportionate-product-design-review.md) | 中文

## 问题

本 fork 先前要求所有普通的用户可见变更都获得独立人工产品/设计结论，即使其行为可逆且可直接验证所作声明。个人 fork 无法可靠获得外部评审，因此这项规则可能使其他方面已充分验证的工作长期无法集成。评审仍需根据后果提供独立审视，并保留对重大变更的人工和所有者决策权限。

## 提案

[Client UI/UX skill](../../../skills/dsh-client-ui-ux/SKILL.md#design-review-escalation)负责采用前瞻性的风险比例化产品/设计评审流程。低风险的呈现变更和局部可逆交互需要针对性行为检查及实际组装应用检查；单独评审可选。中风险的有状态用户行为、Activity 持久化以及仅限于用户现有访问权和目标运行时权限的明确确认跨 Session 分派，需要另一个独立只读 Agent 按精确候选版本进行产品/设计评估。若变更涉及持久化、授权使用或外部执行，还需单独的技术/安全评估和针对生命周期的检查。若验收声明依赖实际 Provider 行为，则需直接的实时 Provider 证据。高风险变更仍需合格的独立人工产品/设计评审、适用的技术/安全评审，以及受保护决策所需的明确所有者授权。混合或模糊的变更按可信的最高风险等级处理。

Agent 评估应在可用时标明评审者和模型、角色、精确的已评审 SHA、检查过的交互和证据、发现、结论及限制。结论必须明确标注为 Agent 评估，不能称作人工批准。单独的技术/安全评估和产品/设计评估使用彼此独立的只读上下文。无法获得所需证据时，相关声明仍未通过资格确认。本政策不改变身份验证、原生 Provider 权限、安全控制、受保护转换或合并权限。

若本政策的精确版本经过所有者批准并集成，拟议流程仅适用于之后作出的评审决定。它不会追溯性地使此前的变更通过资格审查，也不会恢复已过期的 Stage 1 例外。PR #53 的一次性例外仍是单个 PR 的历史决定，不构成通用规则。

## 考虑过的替代方案

- **对每项可见变更继续强制人工评审——不采用。** 这能保留独立人工判断，但会让普通可逆工作依赖个人 fork 无法可靠获得的评审者。
- **所有风险等级均允许 Agent 评估——不采用。** 这会把 AI 评审当作身份验证、权限、安全、破坏性和受保护变更的充分替代。
- **按风险调整评审——建议采用。** 低风险和中风险工作可使用精确版本证据及针对性验证的独立 Agent 评估；高风险工作保留人工评审和受保护的所有者决策。若明确确认的操作仍受用户现有访问权和目标权限约束，则仍属中风险。这既保留按比例提供的独立审查，也避免普通工作依赖上游评审名单。

## 验收标准

- Client UI/UX skill 按最高可信风险对混合和模糊变更分类，并为每个等级说明可执行的证据和评审要求。
- Agent 评估应分别执行、只读、针对精确 commit、明确标记，并与人工评审和所有者授权区分。
- 现有身份验证、权限、安全、受保护转变、合并权限和按声明比例选择证据的要求保持不变。
- 政策只有在所有者明确批准精确修订并完成集成后才前瞻性生效；不会追溯性地使 PR #59 或 PR #61 通过资格确认。
- 双语 Agent Note 及其配对记录通过仓库文档门禁。

## 风险

Agent 评估可能遗漏独立人工评审所能发现的可用性或技术问题。混合或陌生变更的风险分类也可能出错；按最高可信等级处理并将模糊情况默认按高风险处理，旨在保守应对。所有者必须批准最终精确文本，政策才能改变当前有效的评审流程。在此之前，现有的人工评审要求仍然有效。
