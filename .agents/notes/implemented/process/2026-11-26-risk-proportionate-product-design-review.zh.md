# Agent Note: 风险比例化的产品/设计评审

Status: implemented

[English](2026-11-26-risk-proportionate-product-design-review.md) | 中文

## 问题

本 fork 先前要求所有普通的用户可见变更都获得独立人工产品/设计结论，即使其行为可逆且可直接验证所作声明。个人 fork 无法可靠获得外部评审，因此这项规则可能使其他方面已充分验证的工作长期无法集成。评审仍需根据后果提供独立审视，并保留对重大变更的人工和所有者决策权限。

## 决策

[Client UI/UX skill](../../../skills/dsh-client-ui-ux/SKILL.md#design-review-escalation)负责风险比例化产品/设计评审流程。所有者批准的精确政策修订版及其集成记录在 [PR #63](https://github.com/ThorStarlord/deepseek-harness/pull/63) 中，该 PR 已集成到 canonical master。本政策前瞻性地适用于集成后的评审决定。

低风险的呈现变更和局部可逆交互需要针对性行为检查及实际组装应用检查；单独评审可选。中风险的有状态用户行为、Activity 持久化以及仅限于用户现有访问权和目标运行时权限的明确确认跨 Session 分派，需要另一个独立只读 Agent 按精确候选版本进行产品/设计评估。若变更涉及持久化、授权使用或外部执行，还需单独的技术/安全评估和针对生命周期的检查。若验收声明依赖实际 Provider 行为，则需直接的实时 Provider 证据。高风险变更仍需合格的独立人工产品/设计评审、适用的技术/安全评审，以及受保护决策所需的明确所有者授权。混合或模糊的变更按可信的最高风险等级处理。

Agent 评估应在可用时标明评审者和模型、角色、精确的已评审 SHA、检查过的交互和证据、发现、结论及限制。结论必须明确标注为 Agent 评估，不能称作人工批准。单独的技术/安全评估和产品/设计评估使用彼此独立的只读上下文。无法获得所需证据时，相关声明仍未通过资格确认。本政策不改变身份验证、原生 Provider 权限、安全控制、受保护转换或合并权限。本政策不会追溯批准此前的评审决定，也不会恢复已过期的 Stage 1 例外。PR #53 的一次性例外仍是单个 PR 的历史决定，不构成通用规则。

## 考虑过的替代方案

- **对每项可见变更继续强制人工评审——不采用。** 这能保留独立人工判断，但会让普通可逆工作依赖个人 fork 无法可靠获得的评审者。
- **所有风险等级均允许 Agent 评估——不采用。** 这会把 AI 评审当作身份验证、权限、安全、破坏性和受保护变更的充分替代。
- **按风险调整评审——已采纳。** 符合条件的中风险工作可使用有精确版本证据和针对性验证的独立 Agent 评估；低风险工作允许选择是否另行评审；高风险工作保留人工评审和受保护的所有者决策。若明确确认的操作仍受用户现有访问权和目标权限约束，则仍属中风险。这既保留按比例提供的独立审查，也避免普通工作依赖上游评审名单。

## 后果

普通可逆 UI 工作不再依赖外部评审者的可用性，同时中风险变更保留独立进行的 Agent 审查，高风险变更仍需合格的独立人工评审。Agent 评估可能遗漏人工评审者能够发现的可用性或技术问题。混合或陌生变更的风险分类也可能出错；按最高可信等级处理并将模糊情况默认按高风险处理，以维持保守处理。身份验证、权限、安全控制、受保护转换、合并权限和按声明比例选择证据的要求保持不变。本政策不会追溯性地使此前的 PR 通过资格确认；每项变更仍须提供自身证据并满足适用的结论要求。
