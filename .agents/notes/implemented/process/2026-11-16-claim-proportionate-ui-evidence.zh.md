# Agent Note: 与声明和风险相称的 UI 证据

Status: implemented

[English](2026-11-16-claim-proportionate-ui-evidence.md) | 中文

## 问题

此前的浏览器 GIF 规则曾要求每项用户可见的 GUI 变更都附带真实服务器和真实模型 GIF。对于本地呈现或持久化声明，这项要求可能与实际行为无关；而 GIF 本身也不能证明行为、provider 集成或用户接受。若没有明确的证据标准就替换这一统一规则，可能削弱对实时 provider 行为或受保护交互的审查。

## 决策

UI 审查政策针对每项验收声明及其风险选择证据；混合变更由涉及的最高风险声明决定要求。UI 行为发生变化时，需要有针对性的测试并检查已组装的应用。静态状态使用截图；当序列、时序或中间状态很重要时使用视频。呈现证据不能代替行为测试、必要评审或 provider 证据。不能仅仅因为变更出现在 GUI 中就要求真实模型调用。验收标准声称存在实时 provider 行为时，必须提供直接的真实 provider 证据；缺少该证据时，该声明仍不合格。

对于本地持久化和 Activity 协调，如果相关声明适用，则使用有针对性的行为、重启、无法解析的引用、来源归属和恢复证据，并检查呈现的交互。仅记录的外部交接需要持久化和来源归属证据，并确认记录操作不会启动外部工作。除非验收声明依赖 provider 行为，否则这些声明不要求模型调用。

委派执行和其他外部副作用声明需要有针对性的测试，验证用户明确启动、授权归属、应用对 provider 准入和执行的处理、失败与恢复、来源归属，以及不存在意外执行。评审者检查已组装的交互，并提供当前评审政策要求的独立技术/安全和产品/设计评估。身份验证、权限、身份、破坏性副作用和重要结果声明仍遵循其更严格的评审和授权要求。验收声明称 provider 准入或执行了请求，或返回了实时结果时，必须使用直接真实 provider 证据。确定性测试可以证明应用如何处理执行路径和失败，但不能证明实时 provider 行为。provider 报告与独立验证及用户接受各自不同；每项处置都记录其责任人和证据。无法执行实时 provider 验收标准时，该声明仍不合格。

现有安全和授权政策继续负责权限、身份、破坏性副作用和其他受保护要求。证据选择不会授权受保护的变更，也不会改变评审者资格、评审处置、原生 provider 控制或必要的所有者批准。Stage 1 Agent 辅助评估例外仅适用于 Issue #17–#30，并在 Issue #30 集成时到期；当前和未来工作不得使用该例外。

每项证据都记录所审查的提交、应用来源、相关模式，以及它来自实时 provider、确定性测试、回放还是静态检查。用于判定声明合格的证据必须来自该审查提交和已标明的应用来源。不匹配的证据可以指导复查，但不能用于判定声明合格；替代证据必须来自最终审查树。provider 证据注明 provider 和模型，并将每项报告结果归属到其来源。评审记录区分观察与解释，并说明剩余的不确定性。当风险或声明不明确时，采用较严格的适用要求。所有者批准确切提案并集成 PR #37 后，本政策开始前瞻性生效；它不改变 PR #33 或 PR #34 先前的资格状态。

## 考虑过的替代方案

- **每项 GUI 变更都要求真实模型 GIF。** 这保留了统一的材料规则，也能显示交互序列，但会为本地行为声明强制调用 provider，并可能让人误以为 GIF 已证明它没有测试的行为。
- **所有 GUI 变更只使用测试。** 这免去了录制成本，但不能展示已组装的界面或交互状态，也可能漏掉呈现缺陷。
- **所有 GUI 变更只使用静态截图。** 这能为稳定状态提供直接的呈现证据，但无法显示交互序列或时序，也不能证明 provider 行为。

## 后果

本政策避免为本地呈现或持久化声明调用 provider，同时要求在验收声明依赖实际 provider 行为时检查已组装的应用、运行有针对性的测试并提供直接实时 provider 证据。静态证据仅适用于稳定状态；序列或短暂状态很重要时仍需视频。混合变更采用最高风险要求，分类不明确时采用较严格的要求。本政策依赖对声明的准确分类；验收标准所需证据缺失时，该声明仍不合格。provider 报告仍不同于验证和用户接受。
