# Agent Note: Stage 1 Agent 辅助保障

Status: implemented

[English](2026-11-16-stage1-agent-assisted-assurance.md) | 中文

## 问题

现有 Stage 1 替代方式只允许对低风险和中等风险变更进行单独的 Agent 评估，而已批准票据包含有界的原生 Agent 执行和重要的执行状态报告。即使所有者已经授权该批工作，并且 Agent 评估与行为证据足以证明工作质量，现行规则仍使这些高风险票据依赖人工产品/设计评审。

## 决策

所有者已批准针对 Home Harness Stage 1 Issue #17–#30 的政策修订。集成后的 UI skill 允许在风险相称的独立 Agent 辅助评估和行为证据齐备时，使用该评估替代强制人工产品/设计评审。此例外从政策集成后向前适用，在 Issue #30 集成后到期，不改变票据验收标准，也不授权批次范围以外的工作。

低风险和中等风险变更仍须由独立 Agent 只读评估，并按适用情况提供针对性的行为、持久化、重启和渲染交互证据。高风险变更须由未实现或实质性设计该变更的 Agent 分别进行技术/安全评估和产品/设计评估；条件允许时使用不同 Agent 和独立上下文。评估须注明 Issue、所审查的精确提交、Agent、模型、角色、风险理由、检查的行为、证据、验证、发现和不确定性。

高风险证据须检查当前交互中用户对每项 provider 操作的明确授权、provider 准入和执行路径、身份验证和权限保持不变、错误和恢复、结果归属、来源字段和观察时间，以及不存在非预期执行。打开、重新打开或重启 Activity 都不会启动、恢复或重新布防委派或 Goal 工作。结果更正和注释不得改写 provider 报告、原生记录、其来源或观察时间。条件允许时使用真实 provider 证据。对于无法访问的 provider 路径，可用确定性 provider 测试，但它们只能证明实际测试的行为，不能据此声称完成了真实集成。

此替代方式不授权改变身份验证或授权政策、环境或仓库权限、跨用户身份归属、凭据隐私、原生 Codex 或 Claude Code 安全控制、破坏性影响或无界执行。如果票据需要受保护的变更，应在该行为发生前停止，实现安全且有界的部分，并在加入受保护行为前取得仓库所有者的明确授权。Stage 1 评审授权不包含该权限。缺少验收证据或存在未解决的阻塞发现时，变更仍不具备资格且不得合并。

使用以下保障声明：“已通过有记录的技术验证和独立 Agent 辅助评估完成并获得资格，同时明确报告限制和不确定性。”Agent 评估不是人工评审或批准，不得记录为 **APPROVE**。

## 考虑过的替代方案

- **所有高风险 Stage 1 变更继续要求人工评审。** 这保留独立的人类产品判断，但在没有合格评审者时，即使已有更严格的独立 Agent 评估和直接行为证据，也可能阻塞已批准的批次。
- **将 Agent 评估视为人工批准。** 这会错误说明判断者身份并削弱问责性；采纳的保障声明会明确标明 Agent 辅助评估。
- **将例外扩展至整个仓库。** 通用豁免会削弱无关工作的评审要求；本修订仅适用于 Issue #17–#30，并在 Issue #30 集成后到期。

## 验证

UI skill 明确规定 Stage 1 的适用范围、风险类别、评估角色、证据、排除事项、处置方式和有效期限。每项符合条件的评估记录都注明评审 Agent、模型、角色、所审查的 Issue 和提交、证据、验证、发现、限制及不确定性。适用时须提供针对性的行为检查和直接渲染证据。身份验证、授权、权限、凭据处理、provider 安全控制和执行范围仍受保护。文档检查验证 Agent Note 格式、链接和双语配对；自动化检查不判定评估质量。

## 后果

该政策使获批的 Stage 1 批次可以在缺少合格人工评审者时，依靠有记录的 Agent 辅助评估继续推进。Agent 评估提供的人类产品判断少于人工评审，可能遗漏主观易用性或安全问题。要求不同评审角色、直接证据、针对性行为测试、明确限制，并在受保护的变更前升级决策，可以降低风险，同时不宣称它等同于人工评审。
